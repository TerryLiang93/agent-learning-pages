今日要点

昨天你画好了 Agent 的设计图，今天要把它变成能跑的东西——哪怕很粗糙。核心动作就三步：先做最小可用版本、再用测试用例去"撞"它、最后对照验收标准逐项打勾。别追求一次完美，能跑起来 + 知道哪里坏，今天就算赢。

术语卡片

  • 迭代开发 —— 不追求一次做完美，先做个能跑的粗糙版本，再一轮轮改好。像焊电路板：先飞线点亮，再慢慢优化成 PCB。
  • 测试用例 —— 给 Agent 出的"考题"，输入什么、期望输出什么，写清楚，跑一遍看它对不对。
  • 验收标准 —— 你事先写好的"及格线"，比如"能识别 3 种意图""错误时不崩溃"，逐条对照打勾。

原理精讲

为什么先做"能跑但烂"的版本？

想象你要造一台自动售货机。有两种做法：

  • 做法 A：先把外壳、灯箱、玻璃全做到完美，最后才装出货机构。结果发现出货机构卡币，前面全白做。
  • 做法 B：先用纸箱 + 一个弹簧做个"投币掉可乐"的丑东西，验证"识别硬币→弹出饮料"这条主线通不通，再慢慢美化。

迭代开发就是做法 B。 软件比硬件更容易改，所以更没理由一次到位。你的 Agent 第一个版本可以：硬编码一些判断、只支持一个场景、报错就打印一堆日志——都没关系，只要核心任务能从头走到尾。

测试用例是干嘛的？

它是你的"探针"。硬件调试时你会拿万用表量几个关键点电压，软件里测试用例就是这些测量点。写 3~5 条就够，比如：

  1. 输入"帮我查天气" → 期望：调用天气工具
  2. 输入"你好" → 期望：正常闲聊，不报错
  3. 输入乱码 → 期望：不崩溃，给出提示

跑完把哪条挂了、为什么挂、怎么修的记下来。这份记录比代码本身还值钱——它是你明天继续改的地图。

动手任务

手机任务（5 分钟）： 打开备忘录，写下你 Agent 的 3 条验收标准 + 3 条测试用例。格式：输入X → 期望Y。这就是你今天的"及格线"和"考题"。

电脑任务（10 分钟）：

  1. 打开你昨天的设计稿，挑最核心的那一条流程（比如"用户提问→Agent 判断→返回答案"），只实现这一条，其它先不管。
  2. 跑你写的 3 条测试用例，每条记录：通过 / 失败 + 现象。
  3. 对失败的，能 5 分钟修就修；修不动就记进"已知问题清单"，别死磕。
  4. 对照验收标准逐项打勾，没达标的也记下来。

产出： 一个能跑的最小版本 + 一份"测试结果 + 已知问题"记录。

AI 工具箱

用 Claude Skills 把"重复动作"打包成技能

【这是什么】Claude 的 Skill 是一个文件夹，里面放说明文档和脚本，告诉 AI"遇到某类任务就按这套流程做"。【有什么用】你调试 Agent 时反复做同一件事（比如"跑测试→整理失败项→生成问题清单"），可以写成一个 Skill，以后一句话触发。【怎么用】建个文件夹，写一个 SKILL.md 说明触发条件和步骤，放进 Claude 的技能目录即可。【实用例子】写个"测试报告 Skill"：输入测试输出，自动整理成"通过/失败/修复建议"三栏表格。这正好配合你今天的调试记录。搜索关键词：Claude Skills 入门。
