原理精讲

先快速回顾昨天的核心内容，就三件事：

1. 工具（Tool）是什么？ 工具就是给 Agent 装上的"外部能力"，比如查天气、算数学、发邮件。Agent 本身不会这些，但它知道"有这些工具可用"，遇到对应需求就去调用。类比：你不会修水管，但你知道手机里有水管工的电话，需要时拨过去。

2. 循环（Loop）怎么转？ Agent 的工作是一个循环：收到问题 → 判断要不要用工具 → 要就调用并拿到结果 → 把结果交给大模型 → 大模型生成最终回答。这个循环会一直转，直到大模型认为"信息够了，可以回答了"才停下来。

3. 异常（Exception）怎么处理？ 工具调用可能失败——网络断了、API 返回错误、参数格式不对。好的 Agent 不能一失败就崩溃，而是要把错误信息反馈给大模型，让它"自我修正"——换个说法重试、换个参数再调、或者直接告诉用户"暂时查不到"。

今天你要做的，就是把这三件事独立串起来。重点不是代码多复杂，而是流程完整：能调工具、能回答、出错能自己兜住。

电脑任务（10 分钟）—— 独立实现

在你之前搭好的 Agent 框架里，完成天气助手：

步骤 1：定义工具。添加一个 get_weather(city, date) 函数，返回模拟天气数据（温度、天气状况）。不需要接真实 API，返回写死的 JSON 就行，比如：

def get_weather(city, date):
    # 模拟数据，真实场景这里会调天气 API
    return {"city": city, "date": date, "temp": 18, "weather": "多云"}

步骤 2：配置工具列表。把 get_weather 注册到 Agent 的工具列表里，并写好描述（"查询指定城市指定日期的天气情况"）。

步骤 3：实现循环逻辑。让 Agent 收到天气类问题时，自动调用 get_weather，拿到结果后结合大模型生成穿衣建议（比如温度低于 15 度建议穿外套）。

步骤 4：测试三个边界情况：

  • 用户问："北京今天天气怎么样？"（正常情况，应返回天气+穿衣建议）
  • 用户问："帮我算一下 23×17"（非天气问题，应正常拒绝或转交其他工具）
  • 用户问："火星明天天气如何？"（城市不存在，应触发异常处理，给出合理回复）

步骤 5：把每一步遇到的问题和你的解决过程记下来，写在项目 README 里。

AI 工具箱

主题：AI Agent 的"编码规范同步"工具

【这是什么】一个叫 norms 的开源小工具（GitHub 搜索关键词：gsttm/norms），用来管理多个 AI Agent 之间的"编码规范"——让不同 Agent 遵守同一套规则。

【有什么用】很多团队同时用多个 AI 编程助手（比如 Cursor、Codex、Copilot），每个 Agent 可能写出风格不一致、甚至互相冲突的代码。这个工具用一个极简的仓库来统一维护规范，让所有 Agent 都读同一份规则文件。

【怎么用】把团队的编码规范（命名规则、注释风格、禁止事项）写成一个配置文件，提交到仓库里。每个 Agent 在开始工作前自动读取这份配置，保证输出一致。

【实用例子】你的 Agent 团队里有 3 个助手分别负责前端、后端和测试。没有统一规范时，一个用 2 空格缩进、一个用 4 空格，代码合到一起就乱了。用 norms 统一后，三个 Agent 生成的代码风格完全一致，review 成本大幅降低。

一句话总结：AI 时代，管代码规范的工具也要"Agent 化"了。
