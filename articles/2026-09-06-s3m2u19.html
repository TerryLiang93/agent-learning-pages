RAG：让 Agent 会'查资料'

2026-09-06 · 真实落地 · 预计 30 分钟

今日要点

今天学 RAG——让 AI 学会“查资料”。你之前用 AI 时它只能凭“记忆”回答，今天之后它能像你查芯片手册一样，先翻文档再回答，还能告诉你答案出自哪一页。这是让 Agent 真正落地到公司内部文档、私有知识库的关键技术。

术语卡片

  • RAG —— 检索增强生成（Retrieval-Augmented Generation）的缩写。大白话：让 AI 先“查资料”再“写答案”，而不是凭空瞎编。
  • 检索 —— 从一堆文档里快速找出跟问题最相关的几段内容，就像你用 Ctrl+F 搜关键词，但比它聪明——能按“意思相近”来找。
  • 文档切分 —— 把一大本手册切成很多小块（比如每 500 字一块），方便检索时精准定位到“哪一段”跟问题相关。
  • 引用 —— AI 回答时标注“我这个答案是根据哪块资料说的”，就像论文写参考文献，让答案可追溯、可验证。

原理精讲

RAG 解决什么问题？

你训练好的大模型，知识截止在训练那天。你问它“我们公司最新的 BMS 固件怎么配置”，它根本不知道——因为这是公司的私有资料，网上没有。

RAG 的思路特别朴素，分三步：

  1. 准备阶段：把你的文档（PDF、Word、手册）全部切分成小块，每块转成“向量”【术语：向量就是把文字变成一串数字，意思相近的文字数字也接近】，存进数据库。
  2. 检索阶段：用户问问题 → 把问题也转成向量 → 在数据库里找“意思最接近”的几块内容。
  3. 生成阶段：把找到的内容 + 用户问题一起塞给大模型 → 模型“看着资料”回答 → 并标注每句话出自哪块资料。

生活化例子：想象你是一个刚入职的硬件工程师，老板问你“板子上电没反应怎么排查”。你不会凭经验瞎说，而是先翻开公司《硬件调试手册》，找到“上电无反应”那一章，照着上面的排查步骤回答，还告诉老板“这是手册第 3.2 节写的”。这就是 RAG——先查书，再回答，带出处。

为什么要切分文档？

如果不切分，整本手册 200 页一次性塞给模型，有两个问题：一是模型“注意力”有限，看后面忘前面；二是检索时没法精准定位，你问“电源指示灯不亮”，它得翻整本书找。切成小块后，检索能精确命中“电源指示灯”那一小段，又快又准。

为什么答案要带引用？

因为 AI 会“一本正经地胡说八道”。带引用后，你能点开出处核对——如果 AI 理解错了原文，你一眼就能发现。这在工程场景尤其重要：AI 说“把 R3 换成 10kΩ”，你得能回去翻 datasheet 确认它没看错。

动手任务

手机任务（5 分钟）：打开任意一个支持联网搜索的 AI 助手（如 ChatGPT、Kimi、豆包），问它一个关于“你手头正在用的某款芯片”的最新问题——比如“STM32F103 现在市场价多少？还推荐新设计用吗？”观察它是否主动引用来源链接。如果引用了，点开链接核对内容是否真的支撑它的回答。这个体验就是 RAG 的“检索 + 引用”过程。

电脑任务（10 分钟）：跑通一个带引用的 RAG 问答示例。推荐用现成工具，不需要写代码：

  1. 打开浏览器，访问 Dify（开源 LLM 应用平台）的云端版：cloud.dify.ai，注册登录（免费额度够用）。
  2. 点击“创建空白应用”→ 选“聊天助手”。
  3. 在左侧“上下文”区域，点击“添加知识库”→ 新建知识库 → 上传一个你手头的 PDF（比如某芯片的 datasheet，或公司某份技术文档）。
  4. 系统会提示“分段设置”，保持默认即可——这就是文档切分，观察一下它默认按多少字符切一块。
  5. 知识库建好后，回到应用，在“提示词编排”里把知识库关联为上下文，然后点右上角“发布”。
  6. 在调试对话框里问一个文档相关的问题，比如“这个芯片的最大工作电压是多少？”——AI 回答后，看回答下方是否有“引用”按钮，点开核对出处。

能跑通这六步，你就完成了今天的核心目标：会查资料 + 带引用回答。

本周素材精选：agent-skiller —— 可视化搭建 Agent 技能的开源工具

【这是什么】一个开源的可视化构建器，让你用拖拽方式定义“AI Agent 可以一步步执行的技能（Skill）”。GitHub 上 30 星，刚起步但方向很实用。

【有什么用】平时我们教 Agent 做事靠写自然语言提示词，复杂流程容易乱。agent-skiller 把流程变成可视化步骤图——先做什么、再做什么、每步用什么工具，一目了然，比纯文字更可控。

【怎么用】把仓库克隆下来（git clone https://github.com/lattebbrook/agent-skiller），本地启动后，在界面里拖拽创建步骤节点，每个节点填指令，保存后导出成 Agent 能识别的技能文件。

【实用例子】比如你想让 Agent 帮你“写一份硬件测试报告”：步骤 1 读取测试数据文件 → 步骤 2 按模板生成报告 → 步骤 3 保存为 Markdown。三步拖出来连上线，一个可复用的技能就做好了。以后每次说“帮我写测试报告”，Agent 就按这个流程跑。
