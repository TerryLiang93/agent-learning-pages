多 Agent 协作：分工与沟通

2026-09-01 · 协作与质量 · 预计 30 分钟

今日要点

今天学的是“多 Agent 协作”——就是让多个 AI 各管一摊活儿，像公司里不同部门配合一样。你作为硬件工程师，以后大概率会遇到“让 AI 帮我写代码 + 查手册 + 做测试”这种组合需求，单靠一个 AI 对话窗口搞不定。学会给 AI 分工，比让一个 AI 干所有事更靠谱、更高效。

术语卡片

  • 多 Agent —— 多个 AI 程序同时干活，各干各的，互相配合。就像你公司里硬件组、软件组、测试组各管一摊。
  • 编排 —— 一个“总指挥”负责把任务拆开、分给不同 AI、再把结果汇总。就像项目经理派活。
  • 主从模式 —— 一个“老大”AI 管着几个“小弟”AI，老大不干具体活，只负责分配和验收。就像组长自己不写代码，只管分任务。
  • 消息传递 —— AI 之间互相传话/传数据，比如 A 把结果发给 B 当输入。就像同事之间发邮件交接工作。

原理精讲

为什么需要多个 Agent？

一个 AI 就像一个人，能力再强也有局限。比如你让一个 AI 帮你写嵌入式代码，它既要懂硬件寄存器、又要懂 C 语言、还要懂编译错误——全塞给它，它容易“精神分裂”，回答质量下降。分开来：一个专查芯片手册、一个专写代码、一个专查编译报错，各干各的，质量更高。

三种常见模式

  1. 主管分配（主从模式）：一个“主管”AI 负责理解你的需求，拆成小任务，分给几个“专员”AI，最后汇总。适合任务复杂、需要多步骤的。
  1. 专家各管一块：几个 AI 没有上下级，各管一个专业领域，最后把结果拼起来。比如一个管硬件选型、一个管代码、一个管测试用例。
  1. 流水线传递（消息传递）：A 干完传给 B，B 干完传给 C，像工厂流水线。比如 AI 1 写代码 → AI 2 做代码审查 → AI 3 跑测试。

沟通成本与失控风险

人越多协调越难，AI 也一样。多个 Agent 之间传话会出错、会误解、会重复干活。所以原则是：能一个 AI 干完的别硬拆，只有任务确实复杂才上多 Agent。而且一定要有个“总指挥”来兜底，否则容易乱套。

动手任务

手机任务（约 5 分钟）

打开任意 AI 助手（比如 ChatGPT、Kimi、豆包），做这个练习：

  1. 输入：“我要做一个用 ESP32 读取温度传感器的项目。请扮演三个角色：A 是硬件工程师负责选型和接线，B 是嵌入式软件工程师负责写代码，C 是测试工程师负责列测试清单。请按 A → B → C 的顺序依次输出各自负责的内容。”
  1. 观察 AI 如何“扮演”三个角色，输出是否清晰。
  1. 然后追加一句：“现在请把 C 的测试清单发给 B，让 B 根据测试清单修改代码。”——这就是最简单的消息传递。

电脑任务（约 5 分钟）

如果你电脑上装了 Claude Code 或 Cursor 这类工具，试一下：

  1. 让一个 Agent 生成一段 C 代码（比如 LED 闪烁）。
  2. 再让另一个 Agent 审查这段代码，指出问题。
  3. 第三个 Agent 根据审查意见改代码。

如果没装这些工具，就用手机上的 AI 助手模拟这个过程，效果一样。

AI 工具箱

Saccade —— 给 AI Agent 装“眼睛”的浏览器插件

【这是什么】一个开源的浏览器插件，让 AI Agent 能“实时看到”网页内容的变化，而不是慢吞吞地一遍遍刷新页面。

【有什么用】现在的 AI Agent 操作网页时，经常要反复加载页面才能获取最新内容，非常慢。Saccade 相当于给 Agent 装了一个“实时监控摄像头”，页面一变它立刻知道，不用反复刷新。这解决了 Agent 最大的痛点之一——慢。

【怎么用】在 Chrome 或 Edge 浏览器装这个插件，它会给 AI Agent 提供一个“实时语义视图”接口，Agent 可以直接读取页面的最新状态。

【实用例子】想象你让 AI Agent 帮你盯着某个芯片的价格页面，价格一变它就通知你。没有 Saccade 时，Agent 得每几秒刷新一次页面；有了它，页面一更新 Agent 立刻知道，又快又省资源。
