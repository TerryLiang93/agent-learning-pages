记忆：Agent 怎么'记住'东西

2026-08-15 · Agent 怎么工作 · 预计 30 分钟

今日要点

昨天咱们讲到 Agent 怎么干活——它是一套“大模型 + 工具 + 流程”的组合。但你有没有想过一个问题：你跟同一个 Agent 聊了半小时，它还记得你最开始说了啥吗？

答案是：不一定。 这取决于它的“记忆”是怎么设计的。

今天咱们就搞明白三件事：

  1. 模型本身是个“金鱼”——每次对话它都当第一次见你
  2. 短期记忆——就是它眼前能看到的聊天记录
  3. 长期记忆——就是它把东西“存起来”，下次再翻出来用

学完这个单元，你就能说清楚：为什么 ChatGPT 关了再开就忘了你叫啥，而有些 Agent 隔了一周还记得你的偏好。

术语卡片

短期记忆 —— 模型当前这轮对话里能看到的全部内容（包括你发的消息、它回的话、系统塞给它的提示词）。放在“上下文窗口”里，对话一关就没了。

长期记忆 —— 存在外部地方（文件、数据库）的信息，下次对话时再“调出来”喂给模型看。相当于你记在笔记本上的东西，不会因为关电脑就消失。

向量数据库 —— 一种专门用来“按意思找东西”的数据库。不靠关键词匹配，而是靠“语义相似度”检索。你可以理解为一个超级图书馆，你问“怎么修水管”，它能把“家里漏水怎么办”的书也找出来。

嵌入（Embedding） —— 把一段文字变成一串数字（几百到几千个数字），这串数字能代表这段文字的意思。意思相近的文字，数字也相近。这是向量数据库能“按意思找”的前提。

原理精讲

1. 模型本身没有记忆：每次对话都是“重新开始”

先记住一个最反直觉的事实：

大模型本身没有任何记忆。

它不是一个人，而是一台“每次都在现场答题的机器”。你发给它的每一条消息，它都是第一次看到。

那为什么你跟 ChatGPT 聊天，它看起来记得你刚才说了啥？

因为——它没在“记”，它只是“看得到”。

你每发一条新消息，系统会把从对话开始到现在的所有消息（你发的+它回的）打包在一起，全部塞给模型，模型基于这整坨文字来生成下一句回复。

打个比方：

你不是在跟一个朋友聊天，而是在跟一个“每次都要把聊天记录从头读一遍才能回话”的人聊天。他记得，不是因为他记性好，而是因为你每次都把记录递给他看。

这就是为什么：

  • 对话一长，它就“忘”了最早的内容——因为塞不下了（超出上下文窗口【术语】的限制）
  • 新开一个对话，它什么都不记得——因为聊天记录没递过去

关键结论：模型的“记忆”= 你能塞进上下文窗口的文字量。

2. 短期记忆 = 上下文窗口里的内容

“短期记忆”这个词听起来很玄，其实就是上面说的——当前对话里，模型能看到的所有文字。

包括：

  • 你发的每一条消息
  • 它自己的每一条回复
  • 系统偷偷塞进去的“人设”或“指令”（比如“你是一个耐心的中文老师”）

这些全放在一个叫“上下文窗口”的容器里。这个容器有大小限制，比如 GPT-4 大约是 128K 个 token（token 可以粗略理解为“词”或“半个词”）。

生活化例子：

短期记忆就像你办公桌上能摆下的文件。桌子就这么大，文件多了就得往地上扔。扔下去的文件，你就“忘了”。

所以你会遇到这种情况：跟 Agent 聊了 20 轮，它突然开始答非所问——因为它最开始的几轮对话已经被“挤”出窗口了。

3. 长期记忆 = 把信息存起来，需要时再取

那怎么让 Agent 记住更久远的东西？答案很简单：别靠模型记，靠外部存。

思路是这样的：

  1. 对话结束后，把重要的信息写到文件或数据库里
  2. 下次对话开始时，先把存的东西查出来
  3. 把查出来的内容塞进上下文窗口，让模型“看到”

这就是长期记忆的本质——不是模型记住了，而是系统帮你把旧信息找回来，重新递给模型看。

生活化例子：

你老板记性不好，但他有个好习惯——每次开完会都写备忘录。下次开会前，他先翻备忘录，把要点念一遍。他不是自己想起来的，是“查”出来的。

具体实现方式有很多种，最简单的：

  • 存成一个文本文件，每次对话前把文件内容读出来，拼到提示词里
  • 存进普通数据库（比如 SQLite），按用户 ID 查历史记录
  • 存进向量数据库，按“语义相似度”找到相关内容

4. 向量数据库为什么适合记忆：按“意思相近”检索

普通数据库检索靠关键词匹配——你搜“苹果”，它给你找所有含“苹果”二字的记录。

但记忆有个特点：你想起一件事，往往不是按原文想起来的，而是按“意思”想起来的。

比如你昨天跟 Agent 聊了“家里水管漏水怎么办”，今天你问它“厨房水龙头一直滴水”——这俩字面上几乎没重合，但意思很接近。普通数据库搜不到，但向量数据库可以。

它是怎么做到的？

关键在“嵌入（Embedding）”。

嵌入就是把一段文字转换成一串数字，比如：

“家里水管漏水” → [0.12, -0.34, 0.87, ...]（几百个数字）
“厨房水龙头一直滴水” → [0.15, -0.31, 0.82, ...]（同样的长度）

这串数字能表达文字的意思——意思越接近，数字越接近。这就像给每段话算了一个“语义指纹”。

然后向量数据库做的事很简单：

你给它一段新文字，它把它变成数字串，然后去数据库里找“数字最接近”的那几条记录，返回给你。

生活化例子：

你去图书馆找“怎么做红烧肉”的书，管理员不是按书名搜，而是直接带你去“家常菜”区域——因为那个区域的书“意思上”跟你想要的最接近。

所以长期记忆的典型实现流程是：

对话结束 → 把重要内容做嵌入 → 存进向量数据库
下次对话 → 把用户新问题做嵌入 → 从向量数据库里找最相关的内容 → 塞进上下文窗口 → 模型看到后回答

这就是目前大多数 Agent 框架（LangChain、LlamaIndex 等）里“记忆”模块的标准做法。

动手任务

手机任务（5 分钟）

验证“模型没有记忆”这件事：

  1. 打开任意一个 AI 聊天 App（ChatGPT、Claude、豆包、Kimi 都行）
  2. 发一句话：“记住，我的名字叫张三，我养了一只叫旺财的狗”
  3. 继续聊几句别的话题（比如问“今天天气怎么样”）
  4. 然后问它：“我叫什么名字？我的狗叫什么？”

观察结果： 如果它答对了，说明这个 App 做了长期记忆（帮你把信息存起来了）。如果它答错了或说“我不知道”，说明它只有短期记忆——它“看得到”当前对话里的信息，但对话一刷新就没了。

再做一个动作：把对话关掉，重新开一个新对话，再问同样的问题。看它还记得吗？

这就是短期记忆和长期记忆最直观的区别。

电脑任务（5 分钟，可选）

如果你电脑上有 Python，装一下 chromadb（一个轻量级向量数据库），跑下面这段代码，感受一下“按意思检索”：

pip install chromadb
import chromadb

# 建一个内存版向量数据库
client = chromadb.Client()
collection = client.create_collection("my_memory")

# 存两条记忆
collection.add(
    documents=["用户说：我家的水管漏水了", "用户说：我下周要去北京出差"],
    ids=["mem1", "mem2"]
)

# 查询：意思相近的内容
results = collection.query(query_texts=["厨房水龙头一直滴水"], n_results=1)

print(results["documents"])  # 应该返回“我家的水管漏水了”

跑完后你会看到：你搜的是“厨房水龙头滴水”，但它找出来的是“水管漏水”——这就是向量数据库按意思找的能力。
