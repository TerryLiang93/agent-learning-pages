结业项目（第 1 天）：需求与设计

2026-09-10 · 结业项目 · 预计 30 分钟

今日要点

今天是你结业项目的第一天，目标不是写代码，而是把你要做的事想清楚、写明白。你要选一个能解决自己真实问题的 Agent 项目，然后用大白话写出"需求"和"设计"——就像盖房子之前先画图纸。这一步做好了，后面写代码才不会跑偏、不会越做越大收不住。

术语卡片

  • 需求分析 —— 就是回答三个问题：这东西给谁用？输入什么、输出什么？做成什么样算成功？好比你想做一道菜，先想清楚给谁吃、用什么食材、做到什么味道算好。
  • 设计文档 —— 把"怎么做"写下来的一张纸。不写代码，只写方案：用什么工具、流程怎么走、出了错怎么办。相当于做菜前写的步骤清单，免得炒到一半忘了该放盐还是放糖。
  • Agent —— 一个能自己"想一步、做一步"的 AI 程序。它不是一问一答的聊天框，而是你给它一个目标，它能自己拆步骤、调工具、看结果、再调整，直到把事办完。

原理精讲

做结业项目最容易犯的错：一开始就想做个大的，结果做一个月做不完。 所以今天只干一件事——把范围砍小。

需求分析的核心是三个词：用户、输入输出、成功标准。

  • 用户：这个 Agent 是给谁用的？给你自己，还是给同事？用户不同，要求完全不同。给自己用，界面丑点没关系；给别人用，你就得考虑"他不会配置怎么办"。
  • 输入输出：它吃什么、吐什么？比如"输入一份 BOM 清单，输出缺料警告"——这就算说清楚了。如果说不清输入输出，说明你自己都没想明白它要干啥。
  • 成功标准：怎么算做完了？必须可测量。不说"能帮我省时间"，而说"原来手动查缺料要 10 分钟，Agent 做完后 1 分钟内出结果"。有数字，才算可验收。

设计文档的核心是三件事：工具、循环、容错。

  • 工具：Agent 需要调用什么？比如读 Excel 用 Python 的 openpyxl，发通知用钉钉/微信机器人 API，调大模型用 OpenAI 或本地模型接口。先列出来，不用深入。
  • 循环流程：Agent 不是一步到位的。它要"想→做→看结果→再想"。比如让它读一份规格书，提取参数填表，填完发现格式不对，它就自己调整再填。你画出来这个圈就行。
  • 容错：出错了怎么办？这是硬件工程师最熟的事——你设计电路板一定会考虑"电源反接会烧"。Agent 也一样：API 超时怎么办？大模型返回乱码怎么办？识别不了的文件格式怎么办？不用解决，先写出来"这里有风险"就行。

一句话总结今天：用写需求文档的方式，逼自己把项目想透，而不是急着动手写代码。

动手任务

任务一（手机就能做，约 10 分钟）

打开手机备忘录，回答下面三个问题，各写 3-5 句：

  1. 我要做的 Agent 解决什么问题？给谁用？（只限你自己用也行）
  2. 它的输入是什么、输出是什么？（越具体越好，比如"输入：一份元器件库存 CSV；输出：低于安全库存的器件清单"）
  3. 怎么算成功？给一个可测量的标准（比如"原来需要 30 分钟，它 3 分钟内完成"）。

写完发给自己看一眼，如果这三条别人看完能复述出来，需求就算清楚了。

任务二（电脑任务，约 10 分钟）

打开一个新文档，标题写"项目设计文档——[你的项目名]"，然后填四个小节：

  1. 工具清单：列出你打算用的东西（大模型 API、Python 库、消息通知工具等）。不知道用啥就写"待调研"。
  2. 循环流程：用箭头画出来，比如：读文件 → 调用大模型提取信息 → 校验格式 → 不对就重试 → 输出结果。
  3. 失败处理：列出 3 个"可能出错的地方"，每个写一句"出错了怎么办"。写不出来就写"先报错，人工介入"。
  4. 不做清单：写下你明确不做的事。比如"不做网页界面""不处理 PDF 扫描件"。这是控制范围最重要的一步。

范围自检：如果做完上面这些，你发现项目还是太大，就砍掉一半功能。记住：一个能在 3-5 天内跑通的小项目，远比一个 30 天做不完的大项目有价值。

AI 工具箱

素材：ESP32 保龄球馆控制系统（用 $1,600 替代 $120,000 的设备）

【这是什么】一个硬件工程师用 ESP32 单片机 + AI Agent 辅助，把整套保龄球馆计分控制系统做出来了，成本只有原厂的 1/75。

【有什么用】它证明了一个事：单个硬件工程师 + AI 工具，能拿下以前需要一个团队干的活。 对你来说，核心启发不是"我也要去改装保龄球馆"，而是：AI Agent 能帮你处理那些"看起来不复杂但特别琐碎"的工程活——比如写设备通信协议、解析传感器数据、生成调试脚本。

【怎么用】你可以在自己的结业项目里试试这个思路：让 Agent 帮你写"设备间通信的胶水代码"，或者让它读一份芯片 datasheet 帮你提取寄存器配置要点，而不是只让它写一个孤立的函数。

【实用例子】你手头如果有 ESP32 或 Arduino，可以让 Agent 帮你生成一个"读温度传感器数据并通过 WiFi 发到本地服务器"的完整代码框架，你再自己改引脚和协议细节。
