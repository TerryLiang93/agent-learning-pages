评估与调试：怎么知道 Agent 好不好

2026-09-04 · 协作与质量 · 预计 30 分钟

今日要点

昨天我们讲了怎么把 Agent 拆开、给每一步加“安全带”，今天接着往下走——你要怎么证明这个 Agent 是真好还是假好？光靠“感觉还行”是不行的。今天学三件事：用测试题批量考 Agent、每次改完代码都重考一遍、以及 Agent 出错时怎么查它哪一步想歪了。这是你从“写出能跑的 Agent”到“能对别人负责的 Agent”的关键一步。

术语卡片

  • 评估集 —— 就像驾校的考试题库。你提前准备一批“问题+标准答案”的固定题目，每次改完 Agent 都拿这套题去考它，看分数变高还是变低。
  • 指标 —— 就是“怎么算分”。比如答对的题占总题数的百分比（准确率），或者每道题花了多少钱。指标就是把“好不好”变成“一个数”，有了数才能比较。
  • 日志 —— 就像飞机上的黑匣子。Agent 每跑一步，把“当时看到了什么、想了什么、做了什么决定”都记录下来。出事了翻日志，就能还原它当时的思路。

原理精讲

为什么不能靠“试几个例子”来判断 Agent 好不好？

打个比方：你开发了一个帮人查硬件手册的 Agent。今天你试了 3 个问题，它都答对了，你觉得“不错”。但明天用户问了一个你没试过的问题，它答得稀烂——这时候你才发现问题，但已经晚了。

这就像你焊了一块板子，只测了上电能不能亮，就交付了。结果用户拿到手，一跑特定频率就死机。你不能说“我测的时候是好的啊”——因为你没测到那个场景。

所以正规做法是：准备一套“考试题”，每次改动都考一遍。

这套考试题叫评估集。它长这样：

问题1: "STM32F407 的 TIM2 最高能跑多少 MHz？" → 答案: 84MHz（在 APB1 上）
问题2: "I2C 上拉电阻一般选多大？" → 答案: 2.2kΩ~4.7kΩ，取决于总线电容和速率
问题3: "帮我写一段 UART DMA 接收的初始化代码" → 答案: （一段可运行的代码 + 关键注释）

每个问题配一个“标准答案”或者“评分标准”。然后你写一个脚本，把这些问题批量喂给 Agent，自动打分，最后得到一个指标——比如“35 个问题答对了 31 个，准确率 88.6%”。

为什么每次改动都要重跑一遍？这叫做回归测试【术语：回归测试——改了一个地方，怕把以前好的功能弄坏了，所以把老测试全跑一遍确认没搞坏】。

你改了一行 prompt，本来是想修 A 问题，结果不小心把 B 问题的答案搞砸了。如果你不重跑整套题，你根本发现不了。这跟你改了一个电阻值，结果把另一个引脚的时序搞乱了一样——改动是有连锁反应的。

那如果 Agent 答错了，怎么知道它为什么错？

这就需要日志。你在 Agent 的每一步都加一句“记录”——就像你在代码里加 printf 一样：

第1步：收到用户问题 → "帮我写一段 UART DMA 接收的初始化代码"
第2步：判断意图 → 分类为"代码生成"
第3步：检索知识库 → 找到 3 篇相关文档，分别是……
第4步：选择文档 → 选了第 2 篇（关于 DMA 中断配置的）
第5步：生成回答 → ……

出错了，你就翻日志，看它是在哪一步开始跑偏的。是第 3 步没搜到对的东西？还是第 4 步选错了文档？还是第 5 步代码逻辑本身有问题？定位到具体某一步，才能精准修复，而不是瞎调 prompt。

这三件事合起来，就是 Agent 开发的基本功：有评估集（能批量考）、有回归测试（改完重考）、有日志（错了能查）。

动手任务

任务一（手机就能做，约 5 分钟）

打开你常用的 AI 助手（ChatGPT、Claude 等都可以），做一件事：给它出一道“多选题”，让它不仅给答案，还要把推理过程写出来。比如：

“请回答：I2C 通信中，如果总线电容是 200pF，上拉电阻选 2.2kΩ 是否合适？请分步推理，最后给出结论。”

目的：感受一下“分步推理”和“直接给答案”的区别。你在评估 Agent 时，也需要它把步骤说清楚，你才能判断它是“真会”还是“蒙对的”。

任务二（电脑任务，约 5 分钟）

如果你手头有之前搭的 Agent 代码（不管多简单），做这件事：

  1. 打开你的 Agent 主文件，找到它调用大模型的那一行。
  2. 在调用之前加一行打印：print(f"[步骤1] 用户输入: {user_input}")
  3. 在拿到模型回复之后加一行：print(f"[步骤2] 模型输出: {response}")
  4. 运行一次，观察输出。

如果你还没有代码，就用伪代码在纸上写一下这个流程也行——关键是理解“在关键节点留记录”这个思路。

AI 工具箱

主题：用“测试驱动”的方式开发 Agent（结合 Agentray 的思路）

【这是什么】Agentray 是一个 macOS 上的 Agent 工具，它的特殊之处在于：不用聊天窗口，而是用一个文件夹来跟 AI 交互。你把任务文件丢进文件夹，AI 处理后把结果文件放出来。

【有什么用】这个设计对“评估 Agent”特别有启发——因为文件输入/输出的形式天然适合批量测试。你可以准备 30 个输入文件，丢进去，然后检查 30 个输出文件，自动打分。比在聊天窗口里一个个问高效得多。

【怎么用】你不需要真的装 Agentray，但可以借鉴它的思路：把你的 Agent 改造成“输入一个文件 → 输出一个文件”的形式。比如输入是 question_001.txt，输出是 answer_001.txt。这样你写个循环就能批量跑完整个评估集。

【实用例子】你有一个“写代码注释”的 Agent。你准备 10 个代码文件放在 test_input/ 文件夹里，跑一遍 Agent，得到 10 个注释后的文件放在 test_output/ 里。然后你写个脚本，检查每个输出文件里注释的行数、是否包含关键说明——这就自动完成了评估。
