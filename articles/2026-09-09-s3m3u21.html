结业项目（第 1 天）：需求与设计

2026-09-09 · 结业项目 · 预计 30 分钟

今日要点

今天是你结业项目的第一天。前面学了那么多工具和技巧，今天要解决一个关键问题：你到底要做什么。我们会花 30 分钟把项目从"我有个模糊想法"变成"一张能照着执行的图纸"——包括用户是谁、输入输出是什么、怎么算成功、用到哪些工具、流程怎么走、失败了怎么办。这就像盖房子之前先画图纸，图纸画清楚了，后面施工才不会返工。

术语卡片

需求分析 —— 就是搞清楚"到底要做个什么东西、给谁用、解决什么问题"。好比你想买冰箱，先想清楚是给家里用还是给饭店用、要保鲜还是冷冻、预算多少，而不是直接冲去商场看哪个顺眼。

设计文档 —— 把你想好的方案用文字和图画写下来，让别人（包括未来的你自己）一看就明白"这东西怎么工作"。就像做菜之前写的菜谱，材料多少、先放什么后放什么、火候多大，全写清楚。

原理精讲

为什么先做需求和设计？

你以前写代码可能习惯"想到哪写到哪"。小工具没问题，但结业项目是一个完整的 Agent，涉及多个环节（调用模型、处理输入、存记忆、处理错误），不画图直接开写，大概率会陷入"改一处坏两处"的泥潭。

需求分析的核心是三件事：

  1. 目标用户：谁会用你这个 Agent？是你自己，还是你同事？这决定了"好用"的标准。给自己用的，功能糙一点没关系，能省时间就行；给别人用的，就要考虑别人不会用、不爱用的情况。
  2. 输入与输出：用户给这个 Agent 什么？它返回什么？比如你要做一个"自动整理硬件测试报告"的 Agent，输入是一堆 Excel 原始数据，输出是一份 Word 格式的报告。边界画清楚，才不会做着做着跑偏。
  3. 成功标准：怎么算"做完了"？必须可测量。比如"能把 10 份测试报告在 5 分钟内整理完，格式无错误"——这就是可测的。如果写"让报告整理更高效"，那永远做不完。

设计文档的核心是四个模块：

  • 工具：你打算调用哪些现成的工具？比如用 Claude 的 API 做文本处理，用 Python 读 Excel，用某个库生成图表。画出来，不要放在脑子里。
  • 循环流程：Agent 的主循环是什么？拿"整理测试报告"举例：读文件 → 提取关键参数 → 生成图表 → 写入 Word 模板 → 输出。每一步画出来，后面写代码就是照着填空。
  • 记忆方案：这个 Agent 需要记住什么？比如用户上次用的模板偏好、哪些测试项经常变化。需要存的话，是存在本地文件还是数据库？
  • 失败处理：哪一步最容易出错？Excel 格式不对怎么办？网络断了怎么办？至少想清楚"报错提示用户"这一步。

生活化例子

想象你要做一个"自动提醒交房租"的 Agent。需求分析就是：用户是你自己，输入是每月工资到账短信，输出是"提醒你转账并记账"。成功标准是"每月 1 号收到短信后 5 分钟内提醒，连续 3 个月不漏"。设计文档就是：用短信转发工具接收入账通知 → 用 Python 脚本判断日期 → 调用提醒 App 推送 → 如果没收到短信，当天下午再推一次。就这么简单。

动手任务

手机任务（5 分钟）

打开手机备忘录，写下三个你工作中反复做、耗时且讨厌的事情。每件事用三句话描述：

  1. 我每次都要做什么？
  2. 输入是什么（数据/文件/消息）？
  3. 输出是什么（报告/邮件/表格）？

写完后，选一个最让你头疼的，作为你的结业项目选题。

手机任务（5 分钟）

针对你选的题目，在备忘录里回答四个问题：

  1. 目标用户是谁？（大概率是你自己）
  2. 输入是什么？给一个具体例子（比如"每周五的测试数据 Excel，大概 50 行"）
  3. 输出是什么？给一个具体例子（比如"一封包含关键指标对比的邮件"）
  4. 怎么算成功？写一个可测量的标准（比如"从给出输入到收到输出不超过 3 分钟，数据无错漏"）

写不出来或者觉得模糊，说明题目选大了，回去缩小范围。

AI 工具箱

主题：用 "提示词即产品" 的思路——从 refund-anything-ai-prompt 学到的结构化 Prompt 设计

【这是什么】GitHub 上一个开源项目（⭐47），作者写了一套 AI Prompt，专门用来帮你写"退款请求信"——订阅费、数字产品、酒店预订都能用。搜索关键词：refund-anything-ai-prompt。

【有什么用】它演示了一个关键技能：把一件复杂的事情拆成不同阶段，每个阶段用不同的 Prompt 和策略。不是一句话让 AI"帮我退款"，而是先写礼貌信，不行再升级到法律条款引用，还分 30 多个司法管辖区。

【怎么用】对照你自己的项目，你的 Agent 主流程也可以这样分层：第一层先做最简单的处理，失败就进入第二层更复杂的逻辑。比如你的报告整理 Agent：先尝试自动解析 Excel，格式不对就调用 AI 用自然语言理解，还不行就明确告诉用户"哪个单元格有问题"。

【实用例子】你在设计文档的"失败处理"部分，可以画一个三层漏斗：正常流程 → AI 兜底 → 人工提示。每一层用不同的工具和策略，不要一个 Prompt 想解决所有问题。
