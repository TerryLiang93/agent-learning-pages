自己写一个'对话循环'

2026-08-21 · 环境准备 · 预计 30 分钟

今日要点

昨天我们讲了怎么用代码调用大模型 API，但只说了"问一句答一句"。今天要解决一个更实际的问题：怎么让程序记住你说过的话，实现连续聊天。核心就一句话：大模型本身没有记忆，所谓"多轮对话"，就是每次把之前聊过的内容一起再发给它。我们会写一个命令行小聊天程序，跑通真正的连续对话，并观察上下文变长后发生的变化。

术语卡片

  • 消息列表 —— 就像微信聊天记录里的一条条消息（每条带角色：你是"用户"、AI 是"assistant"），程序把整个聊天记录存成一个列表，每次请求时把这个列表整个发给模型。
  • 多轮对话 —— 你一句、AI 一句，来回多轮。本质不是 AI 有记忆，而是我们把聊天记录反复"喂"给它。
  • 历史消息 —— 之前聊过的所有内容。模型不记得，得靠程序每次把历史消息附带上，它才能"看起来记得"。

原理精讲

想象一个场景：你跟一个非常健忘的朋友聊天。他每次只记得你当下说的最后一句话，之前说过什么全忘光了。怎么让他"看起来记得"？办法很简单——你每次说话前，把之前所有的对话内容都念一遍给他听。

大模型就是这样。它的 API 是无状态的【术语：无状态 = 每次请求都是全新的，它不保留任何之前的对话记录】。你调用一次，它只根据你这次请求里给的内容来回答。

所以"多轮对话"的实现方式极其朴素：

  1. 程序维护一个列表，比如 messages = []
  2. 你每说一句话，就往列表里追加一条 {"role": "user", "content": "你说的话"}
  3. 把整个列表发给模型 API
  4. 模型返回的回答，再追加一条 {"role": "assistant", "content": "AI的回答"}
  5. 回到第 2 步，循环

用代码看更直观：

messages = []  # 这就是"消息列表"

while True:
    user_input = input("你：")
    if user_input == "exit":
        break
    
    messages.append({"role": "user", "content": user_input})  # 把你的话放进去
    
    response = call_api(messages)  # 把整个列表发给模型
    
    messages.append({"role": "assistant", "content": response})  # AI的回答也放进去
    print("AI：", response)

注意关键点：每次请求，messages 都在变长。第一轮只有 1 条消息，第二轮 3 条，第三轮 5 条……这就是为什么聊得越久，请求越慢、越贵——因为每次都要把所有历史重新发送一遍。

动手任务

手机任务（5 分钟）：打开任意一个 AI 聊天 App（比如 ChatGPT、Kimi、豆包），连续问三个问题：

  1. "我叫张三"
  2. "我叫什么名字？"
  3. "刚才我说了什么？"

观察它都能答对。然后新开一个对话窗口，直接问"我叫什么名字？"——它会说不知道。这就是"多轮对话"和"无状态"的区别。App 帮你做了消息列表的管理，你感觉不到而已。

电脑任务（10 分钟）：写一个能连续对话的命令行小程序。

步骤：

  1. 新建文件 chat.py，粘贴以下代码（需要先 pip install openai）：
from openai import OpenAI

client = OpenAI()  # 会自动读环境变量里的 API Key
messages = []  # 消息列表，核心数据结构

print("聊天开始！输入 exit 退出。")

while True:
    user_input = input("你：")
    if user_input.lower() == "exit":
        break
    
    # 1. 把你的话加入消息列表
    messages.append({"role": "user", "content": user_input})
    
    # 2. 把整个历史发给模型
    response = client.chat.completions.create(
        model="gpt-4o-mini",  # 便宜的模型，够用
        messages=messages
    )
    
    ai_reply = response.choices[0].message.content
    
    # 3. AI 的回答也加入消息列表
    messages.append({"role": "assistant", "content": ai_reply})
    
    print("AI：", ai_reply)
    print(f"（当前消息列表长度：{len(messages)} 条）")
  1. 运行 python chat.py，测试对话：
你：我叫张三
AI：你好张三！
你：我叫什么名字？
AI：你叫张三。
你：1+1等于几？
AI：等于2。
  1. 重点观察最后一行打印的"消息列表长度"——每聊一轮，长度 +2。这就是为什么聊久了会变慢变贵。
  1. 进阶观察（可选）：聊到第 10 轮左右，感受一下响应速度是否变慢。如果用的是 GPT-4 这类大模型，差别会更明显。
