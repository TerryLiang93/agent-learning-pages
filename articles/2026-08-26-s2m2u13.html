用现成框架搭 Agent

今日要点

昨天我们学了手写一个 Agent 的底层逻辑，今天换个更聪明的玩法：直接用现成框架来搭。就像你焊电路板，不会每次从晶振和电阻开始焊，而是直接用开发板——框架就是 AI 世界的开发板。学完今天，你能说出框架的核心概念，并花 10 分钟搭出一个带工具的可用 Agent。

术语卡片

  • Agent 框架 —— 别人写好的"半成品工具箱"，帮你把 Agent 的骨架、循环、工具调用都封装好了，你只管填业务逻辑。
  • Agents SDK —— SDK 是"软件开发工具包"的缩写【术语】，就是官方发的一盒乐高积木，里面有拼一个 Agent 需要的所有标准零件。
  • 配置式开发 —— 不写一堆代码，而是像填表单一样，用配置文件告诉程序"我要什么"，程序自动帮你组装好。好比点外卖选套餐，而不是自己从买菜开始做。

原理精讲

为什么要用框架？

昨天你手写 Agent 时，得自己处理"模型返回 → 判断要不要调工具 → 调工具 → 把结果塞回去 → 再问模型"这个循环。这个循环叫 Agent 循环【术语】，是每个 Agent 都少不了的"发动机"。但问题是：这个发动机跟你的业务没关系，每个 Agent 都得装一遍。

框架干的事就是：把发动机造好、调试好，留几个插口给你。你只需要告诉它"我的 Agent 叫什么、能用哪些工具、系统提示词是什么"，它就把 Agent 给你跑起来。

框架的核心概念（以 OpenAI Agents SDK 为例）

框架里就三个核心概念，记住这三个就够用了：

  1. Agent —— 就是你的 AI 助手本体，你给它起名字、写性格（系统提示词）、告诉它能用啥工具。
  2. Tool —— 工具，就是 Agent 的"手脚"。比如查天气的函数、算数学的函数。在框架里，你只需要把一个普通 Python 函数"注册"成工具，框架自动帮你处理"模型想调它时怎么传参数"这件事。
  3. Runner —— 跑腿的。你建好 Agent 后，把任务丢给 Runner，它负责驱动整个 Agent 循环，直到任务完成。

配置式开发长什么样？

对比一下昨天手写的代码和今天用框架的代码：

手写版（昨天）：

# 你得自己写循环、自己处理工具调用的返回格式
while True:
    response = model.call(messages)
    if response.has_tool_call():
        result = call_tool(response.tool_call)
        messages.append(result)
    else:
        break

框架版（今天）：

agent = Agent(
    name="助手",
    instructions="你是一个友好的助手",
    tools=[get_weather]  # get_weather 就是一个普通函数
)
result = Runner.run(agent, "北京今天冷不冷？")

看到区别了吗？手写版你得管"循环怎么转"，框架版你只管"Agent 是谁、能用什么工具"。剩下的脏活累活框架全包了。这就是配置式开发的精髓——你描述需求，框架负责实现。

电脑任务（10 分钟）：如果你电脑上有 Python 环境，按下面步骤搭一个能算数学的 Agent：

  1. 安装框架：
    2. pip install openai-agents
  1. 新建文件 my_agent.py，粘贴以下代码：
from agents import Agent, Runner
import asyncio

# 第 1 步：定义一个普通函数
def multiply(a: float, b: float) -> float:
    """两个数相乘"""
    return a * b

# 第 2 步：把函数注册成工具，塞给 Agent
agent = Agent(
    name="计算助手",
    instructions="你是一个计算器，用户让你算啥你就算啥",
    tools=[multiply]  # 直接把函数名放进来就行
)

# 第 3 步：跑起来
async def main():
    result = await Runner.run(agent, "帮我算 12345 × 6789")
    print(result.final_output)

asyncio.run(main())
  1. 运行：
    2. python my_agent.py

如果看到输出 83810205，恭喜你，你的第一个"框架版 Agent"跑通了！

对比手写版：昨天你写 Agent 时，如果想让模型调工具，得自己写 JSON 格式的工具描述、自己解析模型的工具调用请求。今天你只是写了个普通函数 multiply，框架自动帮你生成了工具描述、自动解析调用、自动把结果传回模型。这就是框架省下的重复劳动。

AI 工具箱

今日干货：Hermes Agent —— 开源 AI Agent 框架

【这是什么】Hermes Agent 是一个开源的 AI Agent 框架，主打"随着你的使用越来越懂你"。核心特点是 Agent 的记忆和行为会随交互持续进化，而不是每次从零开始。

【有什么用】对开发者来说，它解决了 Agent 的"个性化"难题——大多数框架每次对话都是"失忆"的，Hermes 让 Agent 能记住你的偏好、习惯，越用越顺手。

【怎么用】作为开源项目，你可以直接 clone 它的代码库，用 Python 调用它的核心类来构建自己的 Agent。它兼容主流 LLM 接口，不需要额外学一套新东西。

【实用例子】比如你做一个"代码审查 Agent"，用普通框架每次都得重新告诉它"你偏好简洁风格、讨厌过度设计"。用 Hermes，它会在多次审查中自动学习你的反馈，之后直接按你的口味给建议。搜索关键词：Hermes Agent NousResearch
