给 Agent 加记忆：向量数据库入门

2026-08-29 · 让 Agent 更聪明 · 预计 30 分钟

今日要点

昨天我们讲了给 Agent 加记忆的思路，今天来落地。核心就三件事：把文字变成数字（嵌入）、让意思相近的文字数字也相近（相似度检索）、用专门的数据库存这些数字（向量数据库）。学完今天，你就能让 Agent"记得"之前聊过什么，并且能按意思找到相关的内容——不是靠关键词，而是靠语义。

术语卡片

  • 嵌入（Embedding） —— 把一段文字（比如一个词、一句话）变成一串数字。这串数字就像文字的"身份证号"，但特殊之处在于：意思相近的文字，身份证号也长得像。
  • 向量 —— 就是那串数字，一般写成 [0.12, -0.45, 0.78, ...] 这种形式。你可以把它想象成高维空间里的一个点，或者一根箭头的方向和长度。
  • 相似度检索 —— 在数据库里找"哪个向量跟我要找的向量最接近"。接近 = 意思相近，不是字面相同。
  • 向量数据库 —— 专门用来存向量、并能快速做相似度检索的数据库。普通的 SQL 数据库也能存向量，但查起来很慢，向量数据库是专门为这个场景优化的。

原理精讲

先理解嵌入：文字 → 数字

想象你在一个城市里，每个词是一个地点。"苹果"和"香蕉"离得近，"苹果"和"汽车"离得远。嵌入要做的事，就是把每个词（或句子）放到这个"城市"的某个位置。这个位置就是一组数字（向量）。

怎么做到的呢？简单说：用一个训练好的 AI 模型，它读过海量文本，学会了"哪些词经常一起出现、出现在相似语境中"。它给每个词算出一组数字，让意思相近的词数字也相近。

比如：

  • "我想吃苹果" → [0.12, -0.33, 0.56, ...]
  • "我想吃香蕉" → [0.13, -0.31, 0.55, ...] ← 跟上面很接近
  • "今天天气不错" → [-0.42, 0.87, 0.10, ...] ← 离得很远

再理解相似度检索：找最近的邻居

有了向量之后，"找意思相近的内容"就变成了"找数字最接近的向量"。计算两个向量有多接近，常用"余弦相似度"——你可以简单理解成：看两根箭头指向的方向是否一致。方向一致 = 相似度高，夹角越大 = 越不相关。

向量数据库：专门干这个的仓库

普通数据库（比如 MySQL）查数据是按条件匹配，比如 WHERE title = '苹果'。但向量数据库是"给我找跟这个向量最像的 5 个"，它内部用了一些高级算法（比如 HNSW）把向量组织成特殊结构，查起来飞快。

生活化类比：嵌入 = 把每个人按性格放到一个"性格空间"里（爱聊天的在一堆，爱安静的在一堆）。向量数据库 = 一个巨大的"性格地图"，你想找"跟我性格最像的人"，它直接在地图上画个圈，把圈里的人给你。

给 Agent 加记忆的流程：

  1. 用户说了一句话，先用嵌入模型把这句话变成向量
  2. 把这个向量存进向量数据库（同时存原文）
  3. 下次用户提问时，把问题也变成向量
  4. 去向量数据库里找最接近的向量，把对应的原文拿出来
  5. 把原文和问题一起丢给大模型，让它基于这些"记忆"来回答

from openai import OpenAI

# 初始化客户端（假设你本地有 OpenAI 兼容的 API，比如 Ollama 或 vLLM）
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")  # 用 Ollama 举例

# 初始化向量数据库（内存模式，不用装服务）
chroma = chromadb.Client()
col = chroma.create_collection("my_memory")

def add_memory(text):
    """把一段话存入记忆"""
    # 1. 嵌入：把文字变成向量
    emb = client.embeddings.create(model="nomic-embed-text", input=text).data[0].embedding
    # 2. 存入向量数据库
    col.add(ids=[f"mem_{len(col.get()['ids'])}"], embeddings=[emb], documents=[text])

def recall(query, top_k=2):
    """根据问题，检索最相关的记忆"""
    emb = client.embeddings.create(model="nomic-embed-text", input=query).data[0].embedding
    results = col.query(query_embeddings=[emb], n_results=top_k)
    return results["documents"][0]

# 存几条记忆
add_memory("用户叫小明，喜欢喝美式咖啡")
add_memory("用户上周说项目延期了，很焦虑")
add_memory("用户养了一只叫旺财的狗")

# 问一个问题，让 Agent 基于记忆回答
question = "我最近心情不好，你还记得为什么吗？"
memories = recall(question)
print("找到的相关记忆：", memories)

# 把记忆和问题一起发给大模型
resp = client.chat.completions.create(
    model="qwen2.5:7b",
    messages=[
        {"role": "system", "content": f"你是一个有记忆的助手。以下是你之前的记忆：\n{memories}\n请基于这些记忆回答用户。"},
        {"role": "user", "content": question}
    ]
)
print("Agent 回答：", resp.choices[0].message.content)
  3. 运行：python memory_agent.py

如果本地没有 Ollama，也可以把 base_url 改成任意 OpenAI 兼容服务的地址。核心逻辑是：存的时候先嵌入再入库，查的时候先嵌入再检索，最后把检索结果喂给大模型。
